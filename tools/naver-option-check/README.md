# 모먼트 옵션 확인(즐겨찾기 버튼) — 정식판

N30 그룹상품 추적에 넣을 **옵션 상품번호**를 상품 페이지에서 한 번에 모으는 즐겨찾기 버튼입니다.
기획: `~/.config/momentinsight/n30-group/option-fill/formal-plan.md` A절 · 구현 약속: 같은 폴더 `impl-spec.md` 4절.

## 쓰는 법(운영팀)
1. 인사이트 관리자 → 옵션 편집창의 '버튼 설치' 안내에서 파란 **모먼트 옵션 확인** 링크를 즐겨찾기 줄로 끌어다 놓습니다(한 번만).
2. 스마트스토어 상품 페이지를 연 채 즐겨찾기의 **모먼트 옵션 확인**을 누릅니다.
3. "그룹 옵션 n개를 찾았습니다(지금 상품 포함)"가 나오면 번호·이름 표를 눈으로 확인하고 **번호 복사** → 인사이트 옵션 편집창에 붙여 넣고 **미리 보기**.
4. "못 찾음" 또는 "이 페이지는 버튼으로 다 읽지 못했습니다"가 나오면 번호를 내주지 않습니다. 편집창에 손으로 입력하고, 필요하면 **진단 복사**를 개발 담당에게 보내 주세요.

## 하는 일과 하지 않는 일
- 사람이 연 페이지에 **이미 들어 있는 데이터**(`__PRELOADED_STATE__`, JSON 스크립트)만 읽습니다. 네이버나 다른 곳에 요청을 보내는 코드가 없고(시험이 묶은 코드에서 요청·주소 이동·HTML 끼워 넣기 코드를 찾으면 빌드가 멈춤), 아무것도 저장하지 않습니다.
- 경로에 `group` 이 있고 **지금 상품번호가 든 목록만** 씁니다. 추천·관련 상품 구역은 뺍니다.
- 객체 목록은 항목마다 번호 칸을 고르지 않습니다. 칸(productNo·channelProductNo·productId·id·no)마다 모든 항목의 번호 묶음을 따로 만들고 **지금 상품번호가 든 칸**을 씁니다(주소의 번호는 id·channelProductNo 쪽, productNo 는 원상품 번호일 수 있음).
- 이런 때는 번호 표·복사 버튼을 아예 보여 주지 않습니다(거절):
  - 페이지 데이터 일부를 못 읽음(페이지 상태 읽기 오류, JSON 이 깨진 `application/json` 스크립트나 id 에 state·data 가 든 데이터 스크립트, 훑다가 값·키 목록 읽기가 오류 난 곳(읽으면 던지는 getter·프록시, 진단 `readErrors`). 검색용 `application/ld+json`·자바스크립트 코드 스크립트는 못 읽어도 진단에만 셈)
  - 탐색 상한(노드·깊이·5000칸 넘는 목록·목록 수)에 **어디서든** 걸림 — 지금 상품이 없는 목록은 목록 수 상한을 쓰지 않음
  - 고른 칸에 번호가 없는 항목이 하나라도 있음 · `[[번호, 번호], …]` 짝 목록에 지금 상품이 있음
  - 지금 상품번호가 든 칸이 둘 이상이고 번호 묶음이 다름(id 와 productNo 가 서로 다른 번호)
  - 고른 목록 바깥에 지금 상품이 든 그룹 목록(번호 2개 이상, 어느 칸이든)이 또 있고 번호 묶음이 다름(부분·더 큰 목록 포함, 바깥인지는 객체로 가림)
  - 그룹 목록이 여러 조각으로 나뉨: 고른 목록을 품은 조상 목록 안(옵션 축별 묶음·쪽 나눔)에 지금 상품 없는 상품번호 목록이 또 있음, 또는 같은 부모 묶음에 길이가 다르고 원상품 칸이 아닌 상품번호 목록이 있음. 같은 부모 묶음의 목록이 고른 목록과 길이가 같거나 키에 `orig`(origin·original)가 들면(`channelProductNos` 옆 `originalProductNos` 같은 나란한 칸) 조각이 아니라 진단(`chosen.parallel`)에만 적음
  - 지금 상품을 뺀 옵션이 50개 초과 · 너무 큰 숫자형 번호 · 서버 규칙(5~20자리) 밖 번호
- 한 번 훑은 데이터 묶음도 만나는 자리(부모·조상 목록)마다 다시 훑습니다. 같은 쪽 목록이 캐시와 그룹의 둘째 쪽에 함께 걸려 있어도 쪼개짐을 놓치지 않습니다. 순환 참조는 조상으로만 막고, 공유가 많아 일이 불어나면 노드 상한(거절)이 막습니다.
- 복사 내용은 지금 상품 번호를 포함한 번호 목록(한 줄에 하나)입니다. 클립보드가 막힐 때만 번호 칸이 보여 직접 선택해 복사합니다.
- 진단에는 키 경로·개수·값 종류만 담습니다(이름·글자 값 없음, 번호는 찾았을 때만). 키 이름 안의 5자리 이상 숫자(`groupProduct_9988776655` 같은 키 포함)는 `#n` 으로 가립니다.
- 화면은 정해 둔 요소(`PANEL_TAGS`)만 만들 수 있고(링크·그림·스크립트 없음), 빌드는 요청·이동·우회 접근 모양의 코드를 찾으면 멈춥니다.

## 파일
| 파일 | 내용 |
|---|---|
| `src/core.mjs` | 판정(순수 함수). 페이지 상태 + 지금 상품번호 → 찾음/못 찾음/거절, 번호·이름, 진단 |
| `src/panel.js` | 화면(그림자 DOM·textContent 만)·복사. 혼자 돌지 않고 빌드가 core 뒤에 붙임 |
| `build.mjs` | 둘을 묶어 `dist/bookmarklet.js`·`dist/bookmarklet-href.txt`(javascript: 주소) 생성, `--embed` 로 관리자 화면 링크 교체 |
| `test/*.test.mjs` | 판정 단위 시험, 묶은 코드 금지 검사·가짜 화면 실행, 끼워 넣기 시험 |

## 개발 담당
```sh
node tools/naver-option-check/build.mjs                                   # dist/ 만 만듦(저장소에 안 들어감)
node tools/naver-option-check/build.mjs --embed src/pages/admin.html      # 관리자 화면 버튼 갱신
node --test tools/naver-option-check/test/*.test.mjs
```
- `--embed` 는 `<!-- mi-option-check-bookmarklet:start -->` … `<!-- mi-option-check-bookmarklet:end -->` 사이 링크 하나의 `href` 만 바꿉니다. 표식이 없거나 둘 이상이면 아무것도 쓰지 않고 실패합니다.
- core·panel 을 고치면 `--embed` 를 다시 돌려야 합니다(시험 '관리자 화면 버튼이 지금 빌드와 같다'가 알려 줌). admin.html 이 바뀌므로 순위 잠금·배포 검사도 다시 봅니다.
- 자리 수·개수 규칙은 `src/server/naver-rank-option-group.mjs` 와 같아야 합니다. 서버 값이 바뀌면 `core.mjs` 를 맞추기 전까지 빌드와 시험이 멈춥니다.
- `src/core.mjs`·`src/panel.js` 에는 줄 끝 주석을 쓰지 않습니다(빌드가 줄 맨 앞 주석만 걷음).
