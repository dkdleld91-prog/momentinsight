제1조개인정보의 처리 목적

회사는 다음의 목적으로만 개인정보를 처리하며, 목적이 변경되는 경우에는 개인정보 보호법 제18조에 따라 별도의 동의를 받는 등 필요한 조치를 이행합니다.

  1. 서비스 접속 및 이용자 식별 — 대행사·운영팀·광고주에게 발급된 접속 코드로 로그인 요청을 확인하고, 역할(총관리자·운영팀·광고주)에 맞는 화면과 데이터 범위를 제공하기 위함.
  2. 구글 계정 로그인(선택 기능) 처리 — 이용자가 스스로 연결한 구글 계정을 기존 접속 코드와 연결해 두고, 다음 로그인 시 동일한 이용자임을 확인하기 위함.
  3. 구글 캘린더 연동(선택 기능) 처리 — 이용자가 연동을 요청한 경우에 한해, 서비스에 등록된 본인의 일정·업무 항목을 이용자의 구글 캘린더로 내보내고, 이용자의 구글 캘린더 일정을 서비스로 가져와 일정 화면에 함께 표시하기 위함(양방향 동기화).
  4. 서비스 제공 및 운영 — 광고주별 대시보드, KPI, 광고 성과, 보고서·첨부파일, 일정·업무 관리, 네이버 키워드 조회 및 순위 추적, 상품 SEO 점검 기능의 제공.
  5. 운영 비서(‘실장’) 대화 기능 제공 — 총관리자가 입력한 질문에 대해 본인의 일정 요약을 바탕으로 답변을 생성하기 위함.
  6. 보안, 부정 이용 방지 및 안정적 운영 — 로그인 시도 제한(무차별 대입 차단), 감사 로그를 통한 변경 이력 확인, 오류 대응 및 서비스 품질 개선.
  7. 문의 대응 및 고지 사항 전달 — 이용 문의 접수와 회신, 서비스 변경·중단 등 필수 안내.

제2조처리하는 개인정보의 항목

회사는 서비스 제공에 필요한 최소한의 항목만 처리합니다. 서비스는 비밀번호를 사용하지 않으며, 회원가입 과정에서 주민등록번호·계좌정보·결제정보 등 고유식별정보나 민감정보를 수집하지 않습니다.

1) 접속 코드 로그인 (기본)

  • 필수 항목: 대행사 코드 / 운영팀 코드 / 광고주 코드 등 회사가 발급한 접속 코드. 이메일 주소와 비밀번호는 입력하지 않습니다.
  • 자동 생성 항목: 로그인 성공 시 발급되는 세션 식별자(sid)와 CSRF 토큰, 세션 유효기간. 이 값들은 암호화된 세션 쿠키 안에만 담기며 서버 데이터베이스에 별도로 저장하지 않습니다.
  • 운영팀 코드 관리 정보: 팀 이름, 팀 코드, 발급·해지 시각.

2) 구글 계정 로그인 (선택 · 이용자가 직접 연결한 경우에만)

  • 요청 권한 범위(scope): openid, email 두 가지뿐입니다.
  • 수집 항목: 구글 계정 고유 식별자(sub)와 구글 계정 이메일 주소.
  • 이용 목적: 해당 구글 계정을 기존 접속 코드·역할과 연결해 두고, 다음 로그인 시 동일인임을 확인하는 본인 식별 용도로만 사용합니다.
  • 접근하지 않는 정보: Gmail 메일 내용, 구글 드라이브 파일, 연락처, 사진, 프로필 이미지, 그 밖의 어떠한 구글 데이터에도 접근하지 않습니다.
  • 이용자 통제: 관리자 화면에서 언제든지 ‘구글 로그인 연결 해제’를 선택하면 저장된 연결 정보가 삭제되며, 기존 접속 코드 로그인은 그대로 사용할 수 있습니다.

3) 구글 캘린더 연동 (선택 · 이용자가 직접 연결한 경우에만)

  • 요청 권한 범위(scope): 구글 캘린더 접근 권한(https://www.googleapis.com/auth/calendar).
  • 동기화 방향: 연동은 양방향 동기화입니다. 서비스에 등록한 일정이 이용자의 구글 캘린더로 나가고, 이용자의 구글 캘린더 일정도 서비스로 들어와 일정 화면에 표시되고 저장됩니다.
  • 사용하는 캘린더: 서비스는 연동 전용 캘린더를 새로 만들지 않으며, 이용자가 이미 사용 중인 캘린더(기본 캘린더와 구글 캘린더 목록에 있는 캘린더, 구글에서 숨김 처리한 캘린더 제외)를 그대로 사용합니다. 이전 버전에서 만들어진 전용 캘린더 ‘모먼트 인사이트’가 남아 있는 경우에는, 그 안의 일정을 이용자의 기본 캘린더로 옮긴 뒤 해당 캘린더를 삭제해 정리합니다.
  • 수집·저장 항목: 구글 OAuth 리프레시 토큰, 연동한 구글 계정 이메일, 연동 시각, 이용자의 캘린더 목록 정보(캘린더 식별자와 이름, 접근 권한, 기본 캘린더 여부, 쓰기 가능 여부, 캘린더 색, 표시 설정, 증분 동기화 토큰).
  • 가져오는(읽기) 내용: 동기화 대상 캘린더의 일정에서 제목, 시작·종료 일시, 종일 여부, 장소, 설명, 참석자 정보(이메일 주소·표시 이름·응답 상태, 최대 50명), 화상 회의 링크, 일정 색, 반복 규칙, 구글 캘린더·일정 식별자, 구글 캘린더 원본 링크, 구글에서의 최종 수정 시각을 읽어 서비스의 일정 데이터로 저장하고 화면에 표시합니다. 새로 가져오는 대상은 시작 시각이 지난 30일부터 앞으로 365일 사이인 일정이며, 한 번에 동기화하는 캘린더는 최대 25개입니다.
  • 전송(쓰기) 내용: 이용자 본인이 서비스에 등록한 일정·업무 항목의 제목(완료된 일정에는 완료 표시가, 광고주가 지정된 일정에는 광고주명이 머리말로 붙습니다), 시작·종료 일시(시간대 Asia/Seoul), 종일 여부, 완료 여부, 서비스 내부 일정 ID·소속 코드·공개 범위가 위 캘린더의 일정으로 생성·갱신됩니다. 장소, 설명, 참석자, 반복 규칙, 일정 색은 이용자가 일정 편집 화면에서 직접 저장한 경우에만 함께 전송되며, 이용자가 요청한 경우에 한해 화상 회의(Google Meet) 링크가 생성됩니다.
  • 이용자 통제: 관리자 화면에서 ‘연동 해제’를 선택하면 저장된 리프레시 토큰과 연동 정보, 캘린더 목록·동기화 상태가 즉시 삭제되고 이후 동기화가 중단됩니다. 다만 이미 구글 캘린더에 생성된 일정은 이용자의 구글 계정에, 이미 서비스로 가져온 구글 일정은 서비스의 일정 화면에 각각 그대로 남으므로, 필요하면 각각에서 직접 삭제하셔야 합니다.

4) 서비스 이용 과정에서 입력·생성되는 정보

다음 정보는 대부분 법인·사업자의 업무 정보이며, 담당자 이름 등 개인을 알아볼 수 있는 값이 포함될 수 있는 자유 입력란을 포함합니다.

  • 광고주·브랜드 정보: 광고주명, 사업자 상호, 광고주 코드, 브랜드명, 카테고리, 주력 판매처, 공개 요약, 내부 메모.
  • 키워드·순위 추적 정보: 추적 키워드, 상품 URL·상품 ID·쇼핑몰명·상품명, 플레이스 URL·플레이스 ID·플레이스명, 추적 기간과 순위 이력.
  • 성과·보고 정보: KPI 목표와 실적, 광고 성과 수치, 대시보드 스냅샷, 보고서 제목·기간·요약·코멘트, 첨부파일 정보(파일명, 저장 경로 또는 외부 링크), 상품 SEO 점검 결과.
  • 일정·업무 정보: 일정 제목, 유형, 상태, 시작·종료 일시, 공개 코멘트, 내부 메모, 공개 범위, 담당자 지정 값.
  • 일정 캘린더 공유 정보: 공유 캘린더 이름, 참여자 식별 키와 표시 이름, 초대 코드의 해시값과 앞 4자리 힌트, 만료 시각(초대 코드 원문은 저장하지 않습니다).
  • 문의 정보: 이용 문의 시 이용자가 제공한 이름, 연락처, 문의 내용.

5) 자동으로 수집·생성되는 정보

  • 세션 쿠키: 로그인 상태 유지를 위한 암호화 쿠키 1개(제9조 참조).
  • 로그인 시도 제한 기록: 접속 IP 주소를 이용해 만든 SHA-256 해시값과 시도 횟수, 시간 창. IP 주소 원문은 이 용도로 저장하지 않습니다.
  • 감사 로그(audit log): 주요 변경·연동 행위의 종류, 대상 테이블·식별자, 발생 시각과 부가 정보. 부가 정보에 포함될 수 있는 접속 코드, 토큰, 비밀값 등은 저장 전에 자동으로 마스킹됩니다.
  • 서버·인프라 로그: 호스팅 사업자(Vercel)가 서비스 운영·보안을 위해 생성하는 접속 기록(요청 시각, 요청 경로, 응답 상태, IP 주소, 브라우저 정보 등).
  • 브라우저 로컬 저장소(localStorage): 화면 표시 설정값. 예) 안내 배너를 닫아 둔 기간(miHomeDevBannerHiddenUntil), 관리자 화면 표시 상태(miAgencyPublicState:v2), 운영 비서 관련 표시 설정(mi-owner-assistant-standby, mi-owner-assistant-goodmorning, mi-owner-assistant-goodmorning-date) 등. 이 값들은 이용자의 브라우저에만 저장되며 서버로 전송되지 않고, 브라우저의 사이트 데이터 삭제로 언제든 지울 수 있습니다.

제3조개인정보의 처리 및 보유 기간

회사는 개인정보를 수집·이용 목적이 달성되면 지체 없이 파기합니다. 다만 관계 법령에서 보존 기간을 정한 경우에는 그 기간 동안 보관합니다.

항목별 보유 기간
구분 보유 기간
접속 코드 및 계정 관련 정보 계약 종료 또는 이용 중지 시 지체 없이 파기하되, 관계 법령에 따라 보존 의무가 있는 정보는 해당 기간 동안 분리 보관 후 파기합니다.

제8조개인정보의 안전성 확보 조치

회사는 개인정보의 안전성 확보를 위해 다음과 같은 기술적·관리적 조치를 시행하고 있습니다.

  • 세션 정보의 암호화 — 로그인 세션 정보는 AES-256-GCM 방식으로 암호화하고 인증 태그로 위·변조를 검증합니다. 세션 쿠키는 HttpOnly, SameSite=Strict, 운영 환경에서는 Secure 및 __Host- 접두어를 적용해 스크립트 접근과 교차 사이트 전송을 차단합니다.
  • 전송 구간 암호화 — 모든 통신에 HTTPS를 사용하며, HSTS(max-age=31536000; includeSubDomains)와 upgrade-insecure-requests를 적용해 평문 전송을 방지합니다.
  • 요청 위조 방지 — 상태를 변경하는 요청에는 세션에 결합된 CSRF 토큰(x-mi-csrf)을 요구하고, 허용된 출처(Origin)에서 온 요청만 처리합니다.
  • 브라우저 보안 헤더 — 콘텐츠 보안 정책(CSP), X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy, Permissions-Policy 등을 적용합니다.
  • 접근 권한 통제 — 데이터베이스 전 테이블에 행 수준 보안(RLS)을 적용하고, 구글 로그인 연결 정보와 캘린더 연동 정보 테이블은 정책 없는 강제 RLS로 설정해 서버 관리 권한(service_role)에서만 접근할 수 있게 했습니다. 화면별로도 총관리자·운영팀·광고주 역할에 따라 조회 범위를 분리합니다.
  • 로그인 시도 제한 — 동일한 자격 증명과 동일한 IP에 대해 일정 시간 창(기본 15분) 안의 시도 횟수를 제한하며, 이때 IP 주소는 원문이 아닌 SHA-256 해시로만 사용합니다.
  • 감사 로그와 민감정보 마스킹 — 주요 변경·연동 행위를 감사 로그에 기록하되, 접속 코드·토큰·비밀값·쿠키 등 민감한 값은 저장 전에 자동으로 제거 또는 마스킹합니다.
  • 비공개 화면 보호 — 관리자 화면과 광고주 화면은 캐시를 저장하지 않도록(no-store) 하고 검색엔진 색인에서 제외(noindex, nofollow)합니다.
  • 비밀번호 미보관 — 서비스는 비밀번호를 사용하지 않으므로 비밀번호를 저장하지 않으며, 총관리자 접속 코드는 해시값으로 대조합니다.
  • 관리적 조치 — 개인정보 취급자를 최소한으로 지정하고 접근 권한을 정기적으로 점검합니다. 내부 관리계획을 수립·시행하고 있으며, 개인정보 취급자 교육은 연 1회 이상 실시합니다.

제한적 사용(Limited Use) 준수 사항

  • 구글 API로 수신한 데이터는 이용자에게 제공하는 기능을 구현하고 개선하기 위한 목적으로만 사용합니다.
  • 수신한 데이터를 광고 목적으로 사용하거나 제3자에게 이전·판매하지 않습니다.
  • 수신한 데이터로 맞춤형 광고, 데이터 브로커, 신용평가 등 어떠한 형태의 프로파일링도 수행하지 않습니다.
  • 보안 문제 대응, 법령 준수, 이용자의 명시적 동의가 있는 경우를 제외하고 사람이 데이터를 열람하지 않습니다.
  • 일반화·집계되지 않은 구글 사용자 데이터를 인공지능·머신러닝 모델의 학습에 사용하지 않습니다.

1) 구글 계정 식별자와 이메일의 사용 범위

서비스가 요청하는 권한은 openid와 email뿐입니다. 이를 통해 얻는 구글 계정 고유 식별자(sub)와 이메일 주소는 오직 로그인 시 이용자를 식별하고 기존 접속 코드와 연결하기 위한 용도로만 저장·사용하며, 마케팅 발송, 프로파일링, 외부 제공 등 다른 용도로 사용하지 않습니다. Gmail, 드라이브, 연락처 등 다른 구글 데이터에는 접근하지 않습니다.

2) 구글 캘린더 데이터의 사용 범위

구글 캘린더 연동은 이용자가 직접 연결한 경우에만 활성화되며, 양방향 동기화로 동작합니다. 서비스는 연동 전용 캘린더를 새로 만들지 않고 이용자가 이미 사용 중인 캘린더를 그대로 사용해, 이용자가 서비스에 등록한 일정을 그 캘린더로 내보내고(쓰기), 같은 캘린더의 일정을 서비스로 가져옵니다(읽기). 가져온 일정은 이용자 본인의 일정 화면에 표시하고 서비스와 구글 양쪽의 내용을 일치시키는 용도로만 사용하며, 그중 제목·시작 일시·종일 여부·상태는 총관리자가 운영 비서(‘실장’) 대화 기능을 사용할 때 답변 생성을 위해 제5조에 기재한 수탁자에게 전달될 수 있습니다. 캘린더 데이터를 광고에 사용하거나, 인공지능·머신러닝 모델의 학습에 사용하거나, 제3자에게 판매하지 않습니다.

3) 연동 해제 방법

  1. 서비스 내: 관리자 화면에서 ‘구글 로그인 연결 해제’ 또는 ‘구글 캘린더 연동 해제’를 선택합니다. 해제 즉시 서비스에 저장된 연결 정보와 리프레시 토큰이 삭제됩니다.
  2. 구글 계정에서: myaccount.google.com/connections에서 모먼트 인사이트를 선택해 접근 권한을 철회할 수 있습니다.
  3. 이미 구글 캘린더에 생성된 일정은 이용자의 구글 계정에, 이미 서비스로 가져온 구글 일정은 서비스의 일정 화면에 각각 남으므로, 필요하면 각각에서 직접 삭제하시기 바랍니다.

구글 API 서비스 이용자 데이터 정책 전문은 developers.google.com/terms/api-services-user-data-policy에서 확인하실 수 있습니다.
