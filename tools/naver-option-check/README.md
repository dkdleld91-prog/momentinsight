# 모먼트 옵션 확인(즐겨찾기 버튼) — 정식판 2.1.0

N30 그룹상품 추적에 넣을 **옵션 상품번호**를 상품 페이지에서 한 번에 모아 인사이트 옵션 편집창으로 넘기는 즐겨찾기 버튼입니다.
기획: `~/.config/momentinsight/n30-group/option-fill/formal-plan.md` A절 → `advertiser-plan.md` 2A·7절 · 구현 약속: 같은 폴더 `impl-spec.md` 4절 → `advertiser-impl-spec.md` 1·3절.

## 쓰는 법(운영팀·광고주)
1. 인사이트 옵션 편집창의 '옵션 확인 버튼 설치' 안내에서 **모먼트 옵션 확인** 칩을 즐겨찾기 줄로 끌어다 놓습니다(한 번만). 관리자 화면 칩은 관리자 화면(`/admin`)을, 광고주 화면 칩은 광고주 화면(`/client`)을 엽니다.
2. 스마트스토어 상품 페이지를 연 채 즐겨찾기의 **모먼트 옵션 확인**을 누릅니다.
3. 결과창은 한 가지 다음 행동만 보여 줍니다.

| 결과창 | 문장 | 버튼 |
|---|---|---|
| 찾음 | "그룹상품 옵션 N개를 찾았습니다." + 상품명 줄(있으면). N 은 지금 상품을 포함한 그룹 상품 수 | **모먼트에서 확인하고 저장** · 닫기 |
| 상품 페이지 아님 | "스마트스토어 상품 페이지에서 눌러 주세요." (주소의 상품번호가 5~20자리가 아니어도 여기) | 닫기 |
| 확인 못 함(거절·목록 없음 모두) | "이 페이지에서 그룹상품 옵션을 자동으로 확인하지 못했습니다." | **모먼트에서 직접 입력** · 닫기 |

4. 주 버튼을 누르면 인사이트가 새 탭으로 열리고, 그 화면이 편집창에 번호를 채워 미리 보기까지 합니다. **저장은 인사이트에서 사람이 확인하고 누릅니다**(버튼도 인사이트도 자동으로 저장하지 않음). '직접 입력'이면 빈 편집창이 열리고, 버튼이 만든 진단은 인사이트가 서버에 기록합니다(번호 복사·진단 복사 버튼은 2.1.0 에서 없앴습니다).

## 하는 일과 하지 않는 일
- 사람이 연 페이지에 **이미 들어 있는 데이터**(`__PRELOADED_STATE__`, JSON 스크립트)만 읽습니다. 네이버에 요청을 보내지 않고, 이 페이지 주소를 바꾸지 않고, 아무것도 저장하지 않습니다.
- **주소 이동은 고정 인사이트 주소 하나만, 사용자가 주 버튼을 누를 때 새 탭으로** 합니다. 빌드가 그 화면용 주소(`https://insight.momentlabs.co.kr/admin` 또는 `…/client`)를 상수로 박고, 버튼 안에서 주소를 조합하지 않습니다. 창 열기 코드는 `window.open(고정 주소 + "#mi-optfill=" + 값, "_blank", "noopener,noreferrer")` 한 곳뿐이고(빌드가 그 밖의 창 열기·별칭·요청·주소 바꾸기·HTML 끼워 넣기 코드를 찾으면 멈춤), 사람이 마우스·키보드로 누른 것(`isTrusted`)에만 엽니다(페이지 스크립트의 합성 click 무시).
- 넘기는 값은 주소의 `#` 뒤에만 싣습니다(쿼리 없음 — 새 탭을 여는 요청에도 실리지 않음, 인사이트가 받자마자 주소창에서 지움).
  - 찾음: `2.f.<지금 상품번호>.<번호-번호-…>` — 그룹 번호 1~51개(지금 상품 포함, 겹침 없음, 5~20자리).
  - 확인 못 함: `2.r.<지금 상품번호>.<진단>` — 진단은 `{"v":"2.1.0","reason":<이유 코드>,"counts":{…8개 이하},"keys":[…20개 이하]}` JSON 을 base64url 로(2000자 이하, 넘으면 keys 를 뒤에서부터 줄임).
- 경로에 `group` 이 있고 **지금 상품번호가 든 목록만** 씁니다. 추천·관련 상품 구역은 뺍니다.
- 객체 목록은 항목마다 번호 칸을 고르지 않습니다. 칸(productNo·channelProductNo·productId·id·no)마다 모든 항목의 번호 묶음을 따로 만들고 **지금 상품번호가 든 칸**을 씁니다(주소의 번호는 id·channelProductNo 쪽, productNo 는 원상품 번호일 수 있음).
- 이런 때는 번호를 넘기지 않고 '확인 못 함'(직접 입력)으로 갑니다(거절):
  - 페이지 데이터 일부를 못 읽음(페이지 상태 읽기 오류, JSON 이 깨진 `application/json` 스크립트나 id 에 state·data 가 든 데이터 스크립트, 훑다가 값·키 목록 읽기가 오류 난 곳(읽으면 던지는 getter·프록시, 진단 `readErrors`). 검색용 `application/ld+json`·자바스크립트 코드 스크립트는 못 읽어도 진단에만 셈)
  - 탐색 상한(노드·깊이·5000칸 넘는 목록·목록 수)에 **어디서든** 걸림 — 지금 상품이 없는 목록은 목록 수 상한을 쓰지 않음
  - 고른 칸에 번호가 없는 항목이 하나라도 있음 · `[[번호, 번호], …]` 짝 목록에 지금 상품이 있음
  - 지금 상품번호가 든 칸이 둘 이상이고 번호 묶음이 다름(id 와 productNo 가 서로 다른 번호)
  - 고른 목록 바깥에 지금 상품이 든 그룹 목록(번호 2개 이상, 어느 칸이든)이 또 있고 번호 묶음이 다름(부분·더 큰 목록 포함, 바깥인지는 객체로 가림)
  - 그룹 목록이 여러 조각으로 나뉨: 고른 목록을 품은 조상 목록 안(옵션 축별 묶음·쪽 나눔)에 지금 상품 없는 상품번호 목록이 또 있음, 또는 같은 부모 묶음에 길이가 다르고 원상품 칸이 아닌 상품번호 목록이 있음. 같은 부모 묶음의 목록이 고른 목록과 길이가 같거나 키에 `orig`(origin·original)가 들면(`channelProductNos` 옆 `originalProductNos` 같은 나란한 칸) 조각이 아니라 진단(`chosen.parallel`)에만 적음
  - 지금 상품을 뺀 옵션이 50개 초과 · 너무 큰 숫자형 번호 · 서버 규칙(5~20자리) 밖 번호
  - 실행 중 오류(진단 이유 `source_unreadable`, counts `runtimeError: 1`)
- 한 번 훑은 데이터 묶음도 만나는 자리(부모·조상 목록)마다 다시 훑습니다. 같은 쪽 목록이 캐시와 그룹의 둘째 쪽에 함께 걸려 있어도 쪼개짐을 놓치지 않습니다. 순환 참조는 조상으로만 막고, 공유가 많아 일이 불어나면 노드 상한(거절)이 막습니다.
- 진단에는 이유 코드·개수·키 경로만 담습니다(이름·글자 값·상품번호 없음). 키 이름 안의 5자리 이상 숫자(`groupProduct_9988776655` 같은 키 포함)는 `#n` 으로 가리고, 경로의 `[]` 같은 글자는 `_` 로, 40자를 넘는 경로는 끝 쪽만 남깁니다.
- 화면은 정해 둔 요소(`PANEL_TAGS`: div·style·h1·button)만 만들 수 있고(링크·그림·스크립트·글 칸 없음), 빌드는 요청·이동·우회 접근 모양의 코드를 찾으면 멈춥니다.

## 파일
| 파일 | 내용 |
|---|---|
| `src/core.mjs` | 판정(순수 함수). 페이지 상태 + 지금 상품번호 → 찾음/못 찾음/거절, 번호·이름, 진단. 맨 아래 넘기는 값·진단 만들기(`optionFill*`) |
| `src/panel.js` | 화면(그림자 DOM·textContent 만)·주 버튼의 창 열기 한 곳. 혼자 돌지 않고 빌드가 core 뒤에 붙임 |
| `build.mjs` | 둘을 묶고 고정 주소를 박아 두 변형 생성: `dist/bookmarklet-admin.js`·`-admin-href.txt`, `dist/bookmarklet-client.js`·`-client-href.txt`. `--embed` 로 화면 링크 교체 |
| `test/*.test.mjs` | 판정 단위 시험, 넘기는 값·진단 시험, 묶은 코드 금지 검사·가짜 화면 실행, 끼워 넣기 시험 |

## 개발 담당
```sh
node tools/naver-option-check/build.mjs                       # dist/ 만 만듦(저장소에 안 들어감)
node tools/naver-option-check/build.mjs --embed src/pages/admin.html --embed src/pages/client.html   # 두 화면 버튼 갱신
node --test tools/naver-option-check/test/*.test.mjs
```
- `--embed` 는 여러 번 줄 수 있고 파일마다 변형을 정합니다: `src/pages/admin.html` → `…/admin`, `src/pages/client.html` → `…/client`, 그 밖의 파일은 실패.
  `<!-- mi-option-check-bookmarklet:start -->` … `<!-- mi-option-check-bookmarklet:end -->` 사이 링크 하나의 `href` 만 바꿉니다. 표식이 없거나 둘 이상이면 실패하고, 한 파일이라도 실패하면 어느 파일도 쓰지 않습니다.
- core·panel 을 고치면 `--embed` 를 다시 돌려야 합니다(시험 '화면 파일의 버튼이 지금 빌드의 그 화면 변형과 같다'가 알려 줌). admin.html·client.html 이 바뀌므로 순위 잠금·배포 검사도 다시 봅니다.
- 자리 수·개수 규칙은 `src/server/naver-rank-option-group.mjs` 와 같아야 합니다. 서버 값이 바뀌면 `core.mjs` 를 맞추기 전까지 빌드와 시험이 멈춥니다. 넘기는 값의 정규식·진단 칸 규칙·이유 코드(`REASON_CODES`)는 받는 쪽(화면·서버 `options-diag`)과 같아야 합니다(`advertiser-impl-spec.md` 1절).
- `src/core.mjs`·`src/panel.js` 에는 줄 끝 주석을 쓰지 않습니다(빌드가 줄 맨 앞 주석만 걷음).
